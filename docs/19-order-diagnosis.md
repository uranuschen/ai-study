入口：根目录 `main_workflow.py`。综合图：`src/agent_learning/workflows/diagnosis_agent.py`。Tracing 见 [第 69 课](18-tracing.md)。本课相关新加 / 调整代码上方以 `# (70)` 标记。

本课以贯通和验收为主，不再引入新的 Agent 框架。复用第 63 课重试 / 预算、第 64 课业务与 RAG Tool、第 66 课会话裁剪和第 67 课审批校验；旧课入口保留便于拆开学习。订单、支付、退款只读本地 JSON，取消只模拟；没有新增表、真实写操作、后台任务或外部日志服务。

## 主流程与 State

`新问题 → prepare → model → 普通 Tool / 人工审批 → model → finish → END`

模型没有工具请求且返回非空回答时正常完成；业务失败、拒绝、永久错误、有限重试耗尽或预算不足则受控结束。失败说明由程序给出，不再额外请求模型。模型是否使用某个工具由实际 `tool_calls` 决定，不强制每个问题都完整查询订单、支付和退款。

「先查订单、未支付或无退款时及时结束」是本课给模型的工具使用策略，不是写死的业务条件边。权限、参数、预算和人工审批由程序强制校验；具体诊断顺序与回答事实性仍要对真实模型验收。离线预设模型验证的是消息接线、数据保留与保护边界，不证明真实模型永远遵守策略。

State 分成两种生命周期：

- 会话级：messages 与同会话成功模拟取消记录，新问题不清空；历史按完整 user 轮次裁剪，不拆开 assistant / tool 配对。
- 本轮级：run_id、工具结果、次数、重试、用量、费用、Tracing 和结束原因，新问题初始化一次；人工恢复不再经过 prepare，不能重新获得一份预算。

`config = {"configurable": {"thread_id": "..."}}` 用于找到本会话 Checkpoint；可信 `tenant_id` 决定业务权限，两者不能混用。`InMemorySaver` 只在当前进程保留，退出即丢失；不是数据库持久化，也不是并发锁。

## 重试、失败与预算

外层 Agent 和 RAG 内层的每次实际 LLM 尝试，包括失败和重试，都消耗模型次数与 Token / 费用预算。每次业务 Tool 分发及其只读重试都计入 Tool 次数；重复取消返回防重复结果也算一次处理，不能用大量重复请求绕过次数上限，但不会重做模拟动作。预算来自可信入口，不接受用户问题或模型修改。

临时连接 / 超时 / 符合条件的 HTTP 异常才有限重试；已知业务失败、格式错误或永久错误不盲目重试。成功查询但 `data=[]` 表示没有记录，不等于调用失败。RAG 资料不足也要保留其状态和引用边界，不能编造规则或实际到账状态。

模型请求前先检查总步骤、Token、费用和启用的时间预算；缺失 usage 时按保守预留扣账。默认 `ENABLE_TIMEOUTS=False`，逐步 Debug 不会因为时间停留失败，但次数 / Token / 费用限制仍生效。开启后的同步超时是协作式检查，不保证强制取消远端请求；生产真实写操作幂等性仍未实现。

教学单价必须按所用模型自行核对；估算费用不是实际账单，预算不是账号级硬上限。外层模型与 RAG 内层都计入，但一笔模型费用只累计一次。

当前入口直接配置：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `MAX_STEPS` | 10 | 外层 Agent、RAG 内层与失败重试的总 LLM 尝试数 |
| `MAX_TOOL_CALLS` | 12 | Tool 处理尝试数，包含只读重试与防重复处理，不含等待审批 |
| `MAX_RETRIES` | 1 | 每次请求最多额外重试一次 |
| `MAX_TOTAL_TOKENS` | 100000 | 本轮预算记账 Token，可能含未知用量预留 |
| `MAX_COST` | 1.00 CNY | 本轮估算费用预算，不是账号账单限制 |
| 输入 / 输出每百万单价 | 10 / 20 CNY | 仅教学演示；真实运行前核对 |
| `ENABLE_TIMEOUTS` | False | 默认只记录时间，不因 Debug 停顿而超时 |
| `SHOW_TRACE_EVENTS` | True | Console 展示完成事件；关闭后仍保留汇总与 State 记录 |

## 人工确认与重复恢复

模型提出 `cancel_order` 后先校验订单号、可信租户和待支付状态，仅 `A1001` 适合本例；`A1002` 已支付，不支持本课的简化取消规则。确认 / 拒绝绑定本次工具请求，不能替换订单、租户、操作或调用 ID。

第 70 课的待审批 request 在第 67 课五个字段之外增加 `run_id`，恢复值严格等于原 request 加 `decision`。即使新问题或另一会话恰好使用相同订单号、相同模型调用 ID，旧批准的 run_id 也不匹配，不能重放。审批界面只展示操作、订单、租户和模拟模式；原始调用 ID 不打印，内部仍用于协议与审批绑定。

审批节点通过 `interrupt(request)` 暂停；入口使用同一 config 的 `Command(resume=decision)` 交回决定。节点从开头重跑时，interrupt 返回已提供的恢复值，不会把恢复值一次用于所有未来中断。审批确认与模拟执行分节点，避免因为审批重跑而提前执行敏感动作。

普通 Tool 逐条执行并保存队列进度，审批恢复不会重做前面已经完成的查询。同会话已成功模拟的订单再次请求时不重复模拟；到 END 后重复恢复不执行已完成动作。恢复仍沿用本轮预算，审批等待和恢复不能刷新次数。

对应节点是 `prepare_approval_node → approval_node → execute_cancel_node`。执行前再次检查预算、审批与订单当前可用状态。模拟执行抛异常时以 `action_error` 结束，不自动重试，也不记为成功；回答必须说「结果未确认」，不能声称确定未执行或已回滚。此规则为将来接真实敏感操作保留清晰边界，当前演示仍不写业务数据。

模拟结果明确包含模拟来源，JSON 保持不变；此边界只是正常学习路径上的防重复，不是崩溃、回滚、换会话或重启后的 exactly-once 保证。真正取消订单仍需业务系统权限、幂等键、事务和外部结果核对，本课不实现。

## Run / Debug

```bash
.venv/bin/python -B main_workflow.py
```

IDE 使用 `/Users/uranuschen/ai-study/.venv/bin/python`，直接 Run / Debug。普通提问时 `/new` 开新会话，`q` 退出；审批时 `y` / `approve` 确认，`n` / `reject` 拒绝，`q` 退出但不模拟取消，不能在待审批状态开始新问题。

建议断点：入口首次 `graph.invoke()` 与 `Command(resume=...)`；图的 prepare / model；单 Tool 分发；审批 `interrupt()` 与参数校验；独立模拟执行；finish 的失败说明和汇总。Tracing 查看 `TraceRecorder.start()` / `finish()` / `summary()`；内外层预算与模型尝试看 `run_execution.py` 的 `RunExecution.request()`。先跟主流程，再看计数，不必一次单步读完所有预算辅助函数。

用户主动运行时才读取模型配置和请求模型；仅模型选择 RAG 时查询已有知识库，有有效证据时内部还会请求模型。只使用已有本地向量 / 精排模型，不自动下载。本次实现只做离线测试，不宣称真实服务已验证。

## 验收场景

| 场景 | 示例 / 离线设置 | 观察重点 |
|---|---|---|
| 简单查询 | 查询 A1002 的退款记录 | 保留两条同租户记录、来源与更新时间 |
| 多步诊断 + RAG | 检查 A1002 的订单、支付、退款，解释通常到账规则 | 按结果选工具，规则引用不冒充实际到账事实 |
| 无记录 | 查询 A1001 的退款记录；查询不存在订单 | 成功空列表与业务失败分开，不伪装已查询后续工具 |
| 多轮 / 隔离 | 先问 A1002，再追问「它」；随后 `/new` | 同会话有历史，新会话无旧消息；裁剪不拆消息配对 |
| 临时错误恢复 | 离线预设第一次连接失败，第二次成功 | 有限重试、次数与未知用量预留不丢失 |
| 永久失败 | 离线预设不可重试异常 | 保留已有证据，受控结束，不无限循环 |
| 人工确认 / 拒绝 | 取消 A1001，分别确认或拒绝 | 确认才模拟，拒绝不执行；参数绑定与重复恢复边界 |
| 预算耗尽 | 离线设置小步骤 / Tool / Token / 费用预算 | 请求前拦截，不靠恢复或重试重置预算 |

## 5 分钟演示与简设计说明

1. 查询 A1002 退款，检查 Tool 结果与 Tracing。
2. 追问到账规则，展示 RAG 引用、会话历史和内外层模型计数。
3. 取消 A1001，先拒绝，再确认；展示暂停 / 恢复与模拟来源。
4. 运行临时失败恢复和预算耗尽的离线用例，展示有界结束。
5. 对照 run_id 的本轮汇总解释最慢步骤、已知 / 未知 Token 和费用估算。

设计取舍：模型负责选择工具与总结，业务事实与敏感操作边界由确定性函数控制；State 保存消息和本轮证据，Checkpoint 保存执行进度；预算限制下一次请求，Tracing 记录发生过的事情。代码保持普通函数、字典和已有库调用，暂不引入队列、审批数据库、长期 Memory 或外部观测平台。
